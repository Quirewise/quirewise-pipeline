# quirewise-pipeline usage guide

This guide covers the task-level workflows of `Quirewise::Pipeline`. The public
API is declared in `quirewise/pipeline.h`, which includes
`quirewise/convert.h` and `quirewise/status.h`.

## 1. Build and integrate

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=/path/to/quirewise/install
cmake --build build
ctest --test-dir build --output-on-failure
cmake --install build --prefix /path/to/quirewise/install
```

Consumer CMake:

```cmake
find_package(QuirewisePipeline CONFIG REQUIRED)
target_link_libraries(your_app PRIVATE Quirewise::Pipeline)
```

The installed config calls `find_dependency` for Runtime, Image, Page, PDG,
Document, Data, Comic, Subtitle, Vector and Audio. Install all of them into the
same prefix before configuring a consumer. The pipeline is the only Quirewise
package the CLI needs for its default conversion build.

## 2. What the pipeline is

The pipeline is a router, not a codec. `Quirewise::Document` registers the
format readers and owns the document route. The pipeline calls that route first
and then tries the application fallbacks that used to live in the CLI:

| Order | Route | Inputs |
|---|---|---|
| 1 | document | every registered document/image format (EPUB, MOBI, DOCX, ODT, PDF, images, …) |
| 2 | page | DjVu, PDG/PDZ, UVZ, CAJ, CEB (content-probed) |
| 3 | subtitle | SRT, VTT, LRC, ASS, SSA, SAMI, MicroDVD (`*.sub`), TTML/DFXP |
| 4 | comic | CBZ (ZIP), CBT (USTAR) |
| 5 | data | JSON, JSONL/NDJSON, YAML, TOML, XML, OPML, iPynb, vCard |
| 6 | CAD | DXF, DWG |
| 7 | SVG | SVG, SVGZ |
| 8 | audio (check only) | the audio containers supported by `Quirewise::Audio` |

The route number is the order, not a claim that every route understands every
extension. Subtitle, comic, data, CAD and SVG routes select by extension; the
page route probes file contents.

## 3. Options

```c
QwPipelineOptions options = QW_PIPELINE_OPTIONS_INIT;
options.raster_page_mode = QW_RASTER_PAGE_MODE_A4;
options.pdz_page_rule = 1;          /* 1 = body pages */
options.archive_password = "secret";
options.audio_track = 2u;           /* one-based, 0 = default */
```

| Field | Meaning |
|---|---|
| `raster_page_mode` | `QW_RASTER_PAGE_MODE_A4` (0) or `QW_RASTER_PAGE_MODE_IMAGE` (1); default from `QW_PIPELINE_OPTIONS_INIT` is `IMAGE` |
| `pdz_page_rule` | PDZ selection: 0 auto, 1 body, 2 body plus attachments, 3 all |
| `archive_password` | Optional password for CBZ archives (and archive readers that support one) |
| `audio_track` | One-based track for the audio check; 0 selects the default |

`QW_PIPELINE_OPTIONS_INIT` is the only supported initializer. Do not rely on
zero-initialization: zero means A4, while the initializer means `IMAGE`.

The pipeline copies `raster_page_mode`, `archive_password` and `audio_track`
into `QwConvertOptions` for the document route, and passes the whole pipeline
options struct to the fallback routes. `pdz_page_rule` is used only by the PDZ
page reader.

## 4. Recipe: convert one file to PDF

```c
QwPipelineOptions options = QW_PIPELINE_OPTIONS_INIT;
QwConvertReport report;
int status;

memset(&report, 0, sizeof(report));
status = qw_pipeline_convert_file("book.epub", "book.pdf", QW_FORMAT_PDF,
                                  &options, &report);
if (status != QW_STATUS_OK) {
    fprintf(stderr, "convert failed (%d): %s\n", status,
            report.note[0] ? report.note : "no detail");
    return 1;
}
printf("wrote %zu bytes, %zu page(s), input format %d\n",
       report.output_size, report.pages_written, (int)report.format);
if (report.skipped_pages)
    fprintf(stderr, "warning: %zu page(s) skipped: %s\n",
            report.skipped_pages, report.note);
```

`output.pdf` must not already exist. The pipeline returns
`QW_STATUS_ERR_IO` and sets `report.note` when the path exists; it never
overwrites, even when the existing file is empty.

## 5. Recipe: check before converting

```c
QwConvertReport report;
memset(&report, 0, sizeof(report));
if (qw_pipeline_check_file("scan.caj", &options, &report) != QW_STATUS_OK) {
    fprintf(stderr, "not readable: %s\n",
            report.note[0] ? report.note : "unsupported input");
    return 1;
}
/* The same options and path can now be converted. */
```

The check runs the document route first. If that route rejects the file, the
fallback routes read/validate it and discard the generated bytes. For page
containers, a file that only partially reads is reported as
`QW_STATUS_ERR_UNSUPPORTED`; `skipped_pages` is also surfaced that way. Audio is
validated by packet scanning only — no decoding or transcoding happens.

Checking can use as much memory as a normal in-memory conversion, because the
fallback routes may build a PDF before discarding it.

## 6. Recipe: convert to TXT or PNG

```c
/* CAD drawing -> UTF-8 text inventory, one entity per line. */
status = qw_pipeline_convert_file("plan.dxf", "plan.txt", QW_FORMAT_TXT,
                                  &options, &report);

/* PNG is document-route only: PDFs and images, no fallback route. */
status = qw_pipeline_convert_file("page.pdf", "page.png", QW_FORMAT_PNG,
                                  &options, &report);
```

Target semantics:

- `QW_FORMAT_PDF` — document route, then page, subtitle, comic, data, CAD and
  SVG fallbacks.
- `QW_FORMAT_TXT` — document route, then the CAD text inventory only.
- `QW_FORMAT_PNG` — document route only. A DjVu, CBZ or DXF file will not
  convert to PNG through the pipeline.

`qw_pipeline_convert_file_to_format` accepts the same three targets plus the
family targets — JSON, JSON Lines, YAML, TOML, vCard, XML, SRT, WebVTT, LRC,
MicroDVD, ASS, SSA, SAMI, SCC, CSV, TSV, HTML, Markdown, DOCX and EPUB — and hands them to
the owning package's writer (document handles HTML/Markdown through the
readers' HTML intermediate). It still never overwrites an output. Any other
target returns `QW_STATUS_ERR_UNSUPPORTED` without touching the file.

## 7. Recipe: batch conversion

```c
static const char *const inputs[] = {"a.docx", "b.cbz", "c.srt"};

for (size_t i = 0; i < sizeof(inputs) / sizeof(inputs[0]); ++i) {
    char output[512];
    QwConvertReport report;
    int status;

    if (snprintf(output, sizeof(output), "out/%zu.pdf", i) >=
        (int)sizeof(output))
        continue;
    remove(output); /* the pipeline refuses to overwrite */
    memset(&report, 0, sizeof(report));
    status = qw_pipeline_convert_file(inputs[i], output, QW_FORMAT_PDF,
                                      &options, &report);
    if (status != QW_STATUS_OK)
        fprintf(stderr, "%s: %d (%s)\n", inputs[i], status, report.note);
    else
        printf("%s -> %s (%zu pages)\n", inputs[i], output,
               report.pages_written);
}
```

Batch callers should decide whether to remove an existing output. The library
will not do it for you.

## 8. Status and report handling

All entry points return the shared `QwStatus` enum:

| Value | Meaning in the pipeline |
|---|---|
| `QW_STATUS_OK` | conversion or check succeeded |
| `QW_STATUS_ERR_INVALID_ARGUMENT` | missing path or an unsupported target |
| `QW_STATUS_ERR_OUT_OF_MEMORY` | allocation failed in a route |
| `QW_STATUS_ERR_IO` | output exists, or a file operation failed |
| `QW_STATUS_ERR_FORMAT` | a route recognized the container but it is corrupt |
| `QW_STATUS_ERR_UNSUPPORTED` | no route accepted the input (or a partial page read for checks) |
| `QW_STATUS_ERR_DECODE` | a route failed while decoding content |
| `QW_STATUS_ERR_EMPTY` | the input is empty |
| `QW_STATUS_ERR_EXTERNAL_DECODER_REQUIRED` | a route needs a decoder not installed |
| `QW_STATUS_ERR_RESOURCE_LIMIT` | a route's documented limit was exceeded |

The pipeline keeps the first concrete route error instead of the generic
"no renderer" result, and copies that route's report. When a route ran, read
`report.note` on failure: it is a 192-byte, NUL-terminated diagnostic and is
often more specific than the status.

`QwConvertReport` fields:

| Field | Meaning |
|---|---|
| `format` | detected input format |
| `output_format` | format actually written |
| `pages_written` | pages produced or reported by the winning route |
| `output_size` | bytes written |
| `skipped_pages` | pages that could not be read; nonzero means partial output |
| `note` | 192-byte diagnostic string |
| `stage` | last active conversion stage (`QwConvertStage`) |

Zero the report before every call. On success, `skipped_pages` may still be
nonzero; the CLI prints a warning in that case. On failure, do not use the
output file.

## 9. Memory, lifetime and threading

- The pipeline retains no pointers after returning. Paths are read only during
  the call; options including `archive_password` are borrowed.
- Output is written directly to `output_path`. Fallback routes build the PDF in
  memory first, then write it.
- There is no global mutable state, so independent calls may run on separate
  threads. There is no file locking: two calls targeting the same output path
  can both pass the existence check, and the result is unspecified. Serialize
  writers that share a path.
- Input files may be replaced between the check and the conversion; the two
  calls do not share a cache.

## 10. Limits and behavior notes

- Routes enforce their own limits and return `QW_STATUS_ERR_RESOURCE_LIMIT`.
  The pipeline adds no global cap. For example, the CAD route caps input at
  256 MiB and extracted text at 8 MiB.
- An existing output is never overwritten. Fallback writes remove the partial
  file after a short write or close failure. The document route may leave a
  partial output on a failed write, matching `Quirewise::Document`'s contract;
  remove such a file before retrying.
- A failed conversion reports the first non-`UNSUPPORTED` route error. A file
  that every route declines returns `QW_STATUS_ERR_UNSUPPORTED`.
- Check mode produces no output file, but page mode, PDZ page selection, the
  archive password and the audio track still affect what the routes read.
- Paths are UTF-8. On Windows the library converts them and opens with
  `_wfopen`, so CJK and emoji file names work.
- The pipeline does not change or extend `Quirewise::PDG`; PDG is consumed as
  installed.

## 11. Related packages

- `Quirewise::Document` — registered format routes, layout and PDF output.
- `Quirewise::Page`, `Quirewise::PDG` — page container readers.
- `Quirewise::Subtitle`, `Quirewise::Comic`, `Quirewise::Data`,
  `Quirewise::Vector`, `Quirewise::Audio` — the fallback routes.
- `Quirewise::Image` — raster pages used by page/comic/SVG fallbacks.
- `Quirewise::Runtime` — status and format enums.
